## 1. Overview

Expense Tracker is a React-based web application designed to help students manage and monitor their daily expenses. It provides a simple and organized way to record expenses, categorize spending, set budgets, and review spending reports.

The system helps students become more aware of where their money goes by providing an easy-to-use dashboard and organized expense records instead of relying on manual notes or spreadsheets.

## 2. Setup and installation

**Prerequisites:**

* Node.js (v18 or newer)
* npm (Node Package Manager)
* Git
* A Supabase account for the database

**Step 1: Clone the repository**

```bash
git clone https://github.com/HAU-6APSI/Initial-Expense-Tracker.git
cd Initial-Expense-Tracker
```

**Step 2: Install dependencies**

Install the project dependencies:

```bash
npm install
```

**Step 3: Environment and configuration**

The application uses environment variables for its Supabase configuration.

Create a `.env` file in the project root:

```env
VITE_SUPABASE_URL=your_supabase_project_url
VITE_SUPABASE_PUBLISHABLE_KEY=your_supabase_publishable_key
```

Do not commit the `.env` file to GitHub. Sensitive credentials should be stored in environment variables.

**Step 4: Database Setup**

The application uses Supabase PostgreSQL for storing expense and budget information.

The required database tables should be created in the Supabase SQL Editor before running the application.

## 3. How to run it

From the project directory, start the Vite development server:

```bash
npm run dev
```

Open the local URL shown in the terminal, usually:

```text
http://localhost:5173
```

You should see the **Expense Tracker Dashboard**.

## 4. Features and usage

Expense Tracker provides several main functions:

1. **Dashboard:** View total spending, budget information, and recent expenses.
2. **Expenses:** Add, view, edit, and delete expense records.
3. **Categories:** Organize expenses into categories such as Food, Transportation, School, and Others.
4. **Budget:** Set a spending limit and monitor current spending against the budget.
5. **Reports:** Review spending based on different expense categories.
6. **Expense Details:** Store important information such as amount, category, date, and description.

### Primary Flow

1. Open the Dashboard.
2. Go to the Expenses page.
3. Add an expense by entering the amount, category, date, and description.
4. Save the expense.
5. View the updated spending information on the Dashboard.
6. Edit or delete an expense when necessary.
7. Set a budget to monitor spending.
8. Use Reports to review spending by category.

## 7. Security and privacy checklist

* **`.gitignore` includes `.env`**: Yes, environment files containing credentials should not be committed.
* **No sensitive files committed**: Yes, credentials and private environment files are excluded from the repository.
* **`.env.example` has placeholders**: Yes, environment variables should use placeholder values in the example file.
* **No Supabase credentials hardcoded**: Yes, Supabase configuration is provided through environment variables.
* **No database passwords committed**: Yes, database credentials are not stored directly in the source code.
* **No personal student data included**: The application does not require real student information for its core expense-tracking features.
* **Expense data**: Expense records are stored for the purpose of helping users monitor their spending.
* **Database access**: Supabase is used for database storage and access.
* **Input validation**: Expense and budget inputs are validated to help prevent invalid records.
* **No payment processing**: The application does not process actual payments or connect to bank accounts.
* **No financial account credentials collected**: Users are not required to provide banking or credit-card credentials.
* **No sensitive financial account information**: The application is an expense-recording tool and does not access users' bank accounts.
* **No real classmates' data required**: Testing can be performed using fictional expense information.

## 8. Known issues and next steps

**Known Issues:**

* The application requires the correct environment variables to connect to Supabase when deployed.
* The application depends on the Supabase database being properly configured.
* The development environment and production environment require separate configuration.
* The application currently focuses on basic expense and budget tracking rather than advanced financial planning.

**Next Steps:**

* Improve the reporting and data visualization features.
* Add more detailed monthly and yearly spending summaries.
* Improve mobile and tablet responsiveness.
* Add additional budget monitoring features.
* Improve validation and error handling.
* Continue improving the user interface and accessibility.
* Add additional testing for expense and budget operations.
