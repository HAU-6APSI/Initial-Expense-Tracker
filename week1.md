My goal this week

My goal was to take the Expense Tracker for Students concept from Documents 1–3 (proposal, wireframes, design system) and turn it into an actual running React app. Specifically, I wanted the four routes (Dashboard, Expenses, Budget, Reports) navigable with real routing, the repeated pieces identified in the wireframes (Navbar, ExpenseRow, BudgetBar, StatCard, ExpenseForm, CategoryPill, Button) built as real components instead of copy-pasted markup, and the app actually styled using the colours, fonts, and spacing from my Document 3 design system rather than default, unstyled HTML.

What I did

I scaffolded a React app with Vite and installed react-router-dom to set up the four routes: / (Dashboard), /expenses, /budget, and /reports. I broke the repeated wireframe pieces into components, split into atoms (Button, CategoryPill), molecules (StatCard, ExpenseRow, BudgetBar, ExpenseForm), and an organism (Navbar), matching the breakdown from Document 2. I installed and configured Tailwind CSS and lucide-react, then mapped my Document 3 tokens (--color-primary, --color-accent, etc.) into tailwind.config.js so the actual utility classes pull from the same palette instead of arbitrary values. I also pushed the UI past a generic template look by styling around a "ledger / receipt" concept — dotted leader lines on expense rows, a stamped-badge look on stat cards, category icons, and a gauge-style budget bar — after getting feedback that the design needed more identity. Each page currently uses hard-coded mock data so the whole thing is clickable end to end (adding and deleting an expense already updates the screen, even though nothing persists yet).

What blocked me

I hit npm error Missing script: "dev" the first time I tried to run the app — I had only copied the src folder contents onto my machine and was running npm run dev from inside that loose folder, not realizing package.json (which is what actually defines the dev script) has to live at the project root, one level up from src. Separately, when I extracted a zip of the project, I dragged the files out manually instead of using "Extract All," which dumped package.json, index.html, and src loose into my Downloads folder mixed in with unrelated files — I had to make a dedicated project folder and move everything into it by hand. Right now I'm also stuck on a blank white page: npm run dev runs successfully and localhost:5173 loads, but nothing renders and there's no visible error overlay, so I'm still working through the browser DevTools console to find the actual JavaScript error.

What I learned

I learned that a folder of source files is not the same thing as a runnable project — without package.json, index.html, and a build config sitting at the root, npm has nothing to run, no matter how correct the component code inside src is. I also learned that how you extract a zip matters more than I expected: right-clicking and choosing "Extract All" keeps everything contained in its own folder, while manually dragging files out scatters them and makes the project easy to break by accident. On the React side, actually building the components Document 2 identified (instead of just diagramming them) made it obvious why breaking things out matters — ExpenseRow alone is reused in both the Expenses list and the Dashboard's recent-expenses preview, and if it weren't a component I'd be maintaining that markup in two places. I'm still mid-way through learning how to diagnose a silent failure (a page that loads with no console-visible error at first glance) instead of a loud one, which is the debugging skill I'm actively building right now.
