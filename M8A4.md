# Weekly Increment Report

## Week 2 (October 2026)

### What changed this week

* **Expense Management:** Implemented the main expense tracking functionality, allowing users to add, view, edit, and delete expense records.
* **Expense Categories:** Added categories such as Food, Transportation, School, and Others to help users organize their spending.
* **Dashboard:** Created a dashboard that displays total spending, recent expenses, and budget information in a simple and user-friendly layout.
* **Budget Management:** Added functionality for setting and updating spending limits and monitoring expenses against the user's budget.
* **Reports:** Added spending reports that organize expenses by category to help users understand where their money is being spent.
* **React Frontend:** Developed the application using React and organized the interface into reusable components and pages.
* **API Integration:** Connected the React frontend to the application's API for expense and budget operations, including creating, updating, retrieving, and deleting records.
* **Supabase Database:** Integrated Supabase PostgreSQL for storing expense and budget data.
* **Error Handling:** Added error messages for failed API requests, including handling cases where the API returns an invalid or non-JSON response.
* **Deployment Preparation:** Prepared the application for deployment through Vercel and configured environment variables for the production environment.
* **GitHub Repository:** Updated and pushed the completed project to the HAU-6APSI `Initial-Expense-Tracker` repository.

### Why

* **To make expense tracking easier:** Students can record and organize their daily expenses instead of manually tracking them using notes or spreadsheets.
* **To improve financial awareness:** The dashboard, budget monitoring, and reports help users understand their spending habits.
* **To meet the full-stack requirements:** The project uses React for the frontend, an API for application operations, and Supabase PostgreSQL for data storage.
* **To improve usability:** The interface was designed to make common actions such as adding, editing, and deleting expenses simple and easy to understand.
* **To prepare the project for deployment:** Environment variables and production configuration were prepared so the application can run outside the local development environment.

### What broke or what I got stuck on

* **API Connection During Deployment:** The application worked correctly on localhost, but the deployed Vercel version initially returned a 404 response when requesting API endpoints because `/api` was not pointing to the correct production API.
* **Expense Update Issue:** The update functionality required debugging to make sure edited expense information was correctly sent through the API and reflected in the application.
* **Vercel Build Issue:** Vercel initially encountered a `vite: Permission denied` error during the build process, requiring the project dependencies and build configuration to be checked.
* **Environment Variables:** Understanding the difference between local environment variables and Vercel environment variables was necessary to properly configure Supabase and the application's API connection.
* **GitHub Repository:** The project was initially connected to a personal GitHub repository before being moved and pushed to the required HAU-6APSI `Initial-Expense-Tracker` repository.
