Week 2 (October 2026)
My goal this week

My goal this week was to continue improving my Expense Tracker while completing the required documentation updates for M8A5 and the full-stack development requirements for M8A9. I wanted to make the main expense features work properly, connect the frontend to the backend and database, and update the project documentation to clearly explain how the system works, how to run it, and what features were completed.

What I did

I improved the Expense Tracker by completing the main expense management features, including adding, viewing, editing, and deleting expenses. I also added categories such as Food, Transportation, School, and Others. I worked on the Dashboard, Budget, and Reports sections to make the system more useful for students who want to monitor their spending.

For the full-stack part, I connected the React frontend to the Express API and PostgreSQL/Supabase database. I also improved the API service and error handling so that problems with API requests would provide clearer messages. I tested the application and worked on fixing an issue where expenses could not be updated properly.

For M8A5, I updated the project documentation to reflect the current state of the Expense Tracker. I documented the project overview, setup instructions, environment variables, features, project structure, known issues, and future improvements. I also updated the Weekly Increment Report to record the changes and problems encountered during development.

What blocked me

One of the main problems I encountered was the API connection after deploying the application to Vercel. The application returned a 404 error because the frontend was requesting /api/expenses, but the API route was not correctly available in the deployed environment. I also had an issue with updating expenses, which required checking the frontend, API request, and backend route.

I also experienced a Vercel build error involving Vite permissions. Aside from coding problems, keeping the documentation updated while the project was still changing was also challenging because I needed to make sure that the README and reports matched the actual features and current setup of the project.

What I learned (Development, Documentation, and AI Reflection)

This week, I learned that documentation is an important part of software development because it helps explain how the project works and how other users or developers can run and understand it. I also learned that documentation needs to be updated whenever major changes are made to the application.

I also learned more about how React, Express, REST APIs, and PostgreSQL/Supabase work together in a full-stack application. A feature may work correctly on the frontend, but it still depends on the API and database to work properly.

I used AI as a development assistant to help me understand errors, troubleshoot problems, improve parts of the code, and organize my documentation. I did not simply copy the suggestions without checking them. I tested the changes and reviewed the results to make sure they worked with my project.

Overall, this week helped me improve both my coding and documentation skills. I became more familiar with full-stack development, API connections, database operations, deployment, GitHub, and using AI responsibly during development.
